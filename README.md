# Сноска

Сервис проверки документов на соответствие 152-ФЗ «О персональных данных» и правилам оформления (ГОСТ Р 7.0.97-2016). К каждому замечанию — «сноска»: точная ссылка на статью, часть и пункт нормы с цитатой.

Текущее состояние — веха 4 «Демо и кейс»: лендинг для гостей с записями продукта и честными цифрами, демо-вход в один клик по ролям с ночным сбросом стенда, подключённая модель через внешний API (пачки запросов, кэш ответов, дневной бюджет, цепочка бесплатных моделей, выбор модели замером), нагрузочный тест, продакшен-сборка в Docker с Caddy и резервными копиями, видео и кейс. Веха 1 дала организации и роли, изоляцию тенантов, загрузку DOCX и PDF (включая сканы) с разбором структуры, корпус 152-ФЗ, дизайн-систему, список и просмотр документов. Веха 2 — сама проверка: реестр из 43 проверок (оформление по ГОСТ Р 7.0.97-2016 — правилами, требования 152-ФЗ — языковой моделью только с цитатой найденного фрагмента), результат как документ со сносками и карточками на полях, решения по замечаниям (принято, отклонено, исправлено), ход проверки в реальном времени, страница «Как мы проверяем» с точностью и полнотой на эталонном наборе. Веха 3 — сервис вокруг проверки: автоисправление оформления DOCX новой версией с журналом «было/стало», «Спросить норму» (ответ только с цитатами и ссылками на пункты), тарифы с леджером использования, атомарными лимитами и тестовым провайдером оплаты, API-ключи и подписанные вебхуки с журналом доставок, журнал аудита с экспортом, участники и роли (через Keycloak), пространства со своими ролями, объектное хранилище MinIO, еженедельная проверка новой редакции 152-ФЗ с письмом администратору и консоль оператора платформы.

## Быстрый старт

Нужны Docker с Compose, Python 3.13 и [uv](https://docs.astral.sh/uv/), Node 24 и pnpm 10, Tesseract с русским языком (`tesseract-ocr-rus`). Для пересборки демо-документов — LibreOffice. Нейросети на машине не запускаются: языковая модель и эмбеддинги подключаются только через внешний OpenAI-совместимый API.

```bash
make env            # .env со случайными секретами
make up             # PostgreSQL + pgvector, Redis, Keycloak, Mailpit, MinIO
cd backend && uv sync && cd ..
cd frontend && pnpm install && cd ..
make migrate        # схема БД
make corpus         # 152-ФЗ из снимка портала
make seed           # демо-организации, участники, документы, пространство, тариф, интеграции

# в отдельных терминалах
make api            # http://127.0.0.1:46301
make worker         # фоновые задачи и отправка outbox
make web            # http://localhost:46300
```

`make stand` запускает весь стенд в фоне (контейнеры, API, воркер, веб; журналы — `.run/logs/`), `make status` показывает, что запущено, `make stop` останавливает всё одной командой. Прогоны скриншотов, записей и нагрузочного теста возвращают демо-стенд к сиду, когда заканчиваются. `make demo-refresh` обновляет всё, что зависит от модели (индекс, сброс стенда, перепроверку, замер качества, скриншоты, записи лендинга, видео), `make load` — нагрузочный тест k6 в Docker ([`docs/performance.md`](docs/performance.md)). Продакшен-сборка и выкатка на сервер — [`docs/deploy.md`](docs/deploy.md). `make stop` останавливает контейнеры. Файлы хранятся в MinIO (`SNOSKA_STORAGE_BACKEND=s3`); `snoska storage copy-to-s3` переносит файлы, загруженные раньше в локальную папку. `make watch` проверяет новую редакцию 152-ФЗ сразу (по расписанию — раз в неделю, письмо — в Mailpit). `make recheck` заново проверяет последние версии всех документов (после изменения реестра проверок), `make benchmark` измеряет проверки на эталонном наборе и обновляет [`docs/quality.md`](docs/quality.md).

### Языки

Интерфейс, страницы входа, письма и тексты проверок — на русском и английском. Язык страницы — выбор посетителя (переключатель на лендинге, в меню профиля и на странице входа), иначе язык браузера, иначе английский; API отвечает на языке из `Accept-Language` (без него — по-русски). У каждой проверки один источник — запись реестра с текстами на обоих языках; модель пишет пояснения сразу на всех языках, а «Спросить норму» отвечает на языке спрашивающего. Сами документы и закон остаются русскими и показываются как есть: продукт проверяет российские документы по российскому праву. Новый язык — элемент `Locale` в бэкенде, `LOCALES` во фронтенде, каталог `frontend/messages/<язык>.json`, тексты в реестрах и теме входа.

### Модели

Проверки оформления работают сразу. Юридические проверки по 152-ФЗ и «Спросить норму» используют языковую модель через внешний OpenAI-совместимый API (на стенде — OpenRouter): `SNOSKA_AI_PROVIDER=openai_compatible`, `SNOSKA_LLM_BASE_URL`, `SNOSKA_LLM_API_KEY`, `SNOSKA_LLM_MODEL`, `SNOSKA_EMBEDDING_MODEL`, `SNOSKA_EMBEDDING_DIMENSIONS`, затем `make index`. Для бесплатного тарифа — `SNOSKA_LLM_REQUESTS_PER_DAY` и `_PER_MINUTE` (дневной бюджет и темп), `SNOSKA_LLM_FALLBACK_MODELS` (запасные бесплатные модели), `SNOSKA_LLM_EXTRA_BODY` (например, без рассуждений). Ответы кэшируются по запросу: повторная проверка того же текста не тратит запросов. Без модели юридические проверки отмечаются «модель не подключена», при исчерпанном лимите — ждут следующего дня и проверяются сами.

### Оплата

Подключён тестовый провайдер оплаты (`SNOSKA_PAYMENTS_PROVIDER=test`): переход на тариф дороже открывает его страницу `/pay/test/…` с пометкой тестового режима, решение «оплатить/отклонить» возвращается подписанным уведомлением, и тариф меняется. Деньги не списываются.

### Демо-доступы

Учётные записи и пароли — в [`backend/demo/seed.yaml`](backend/demo/seed.yaml). Организации:

- **ООО «Полярная звезда»** — владелец, юрист, исполнитель и наблюдатель (без права загрузки); пять документов, у положения две версии, приказ — скан. Тариф «Команда»; закрытое пространство «Кадры», где наблюдатель организации — юрист; API-ключ и вебхук на встроенный демо-приёмник.
- **АО «Речной порт»** — владелец и юрист; два документа.
- **ООО «Заря»** — владелец, юрист и наблюдатель; пять черновиков с типичными ошибками из эталонного набора: на них видны замечания и автоисправление; у юриста и владельца — вопросы к норме с готовыми ответами (проверяются по корпусу при сиде, запросов к модели не требуют).
- **ИП Соколова** — новая организация без документов.
- Оператор платформы — `operator@snoska.example`, консоль `/platform`.

С `SNOSKA_DEMO_MODE=true` на `/demo` — вход в один клик: владелец, юрист, наблюдатель, оператор платформы; эти учётные записи защищены от смены роли, а `snoska demo nightly` (или `snoska demo reset`) возвращает демо-организации к сиду.

Вход — через Keycloak со своей темой страниц входа (форма в два шага: e-mail, затем пароль). Realm импортируется при первом запуске Keycloak; чтобы применить изменения `infra/keycloak/realm-snoska.json` к уже созданному realm, удалите его в консоли администратора и перезапустите контейнер — `make seed` заново создаст организации и участников.

## Архитектура

```
backend/src/snoska/
  domain/          модель без ввода-вывода: тенанты, роли и пространства, документы,
                   корпус норм, проверки, аудит, интеграции, тарифы, автоисправление
  ports/           контракты: репозитории, unit of work, хранилище, очередь, парсеры,
                   OCR, LanguageModel, Embedder, источники корпуса, identity, каталог
                   участников, провайдер оплаты, доставка вебхуков, почта
  application/     сценарии: загрузка, разбор, корпус, проверки, администрирование,
                   аудит, интеграции, тарифы, автоисправление, вопросы к норме, операции
  infrastructure/  адаптеры: PostgreSQL (RLS), Dramatiq/Redis, MinIO/S3, python-docx,
                   pdfplumber, Tesseract, OpenAI-совместимый API, Keycloak, pravo.gov.ru,
                   тестовый провайдер оплаты, HTTP-вебхуки, SMTP
  bootstrap/       корень композиции и настройки
  api/ worker/ cli/  точки входа
frontend/src/
  shared/          дизайн-система (токены, компоненты), клиент API, i18n
  features/        оболочка, документы, результат проверки, «Как мы проверяем»,
                   администрирование организации, интеграции, тариф и оплата,
                   автоисправление, «Спросить норму», консоль платформы
  server/          BFF: сессии, OIDC, обращения к API
  app/             маршруты Next.js
```

Зависимости направлены внутрь; это проверяет `import-linter`. Подробности и обоснования решений — в [`docs/architecture.md`](docs/architecture.md).

## Качество

`scripts/gate.sh` — те же проверки, что в CI: размер файлов (≤ 700 строк) и папок (≤ 15 файлов исходников), ruff, mypy `--strict`, контракты импортов, актуальность OpenAPI, pytest (включая интеграционные тесты изоляции тенантов на PostgreSQL), tsc, ESLint, Stylelint (запрет литералов цветов и отступов вне токенов), Prettier.

Скриншоты экранов вехи (390×844, 768×1024, 1280×800, светлая и тёмная тема) — `docs/screenshots/m4/` (прежние вехи — `m1`–`m3`), снимаются `cd frontend && MILESTONE=m4 pnpm screenshots`; состояния исчерпанного лимита модели — набором `m4-limit` в день, когда лимит действительно исчерпан. Видео — `docs/case/video/`, кейс — [`docs/case/`](docs/case/README.md).

Качество проверок на эталонном наборе — [`docs/quality.md`](docs/quality.md).
